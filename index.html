Investigation Walkthrough

01. Resource Exhaustion

Monitoring triggers critical CPU alerts. The web application is returning 503 (Service Unavailable) and 408 (Request Timeout) errors to users.

02. Access Log Triage

Tailing the Nginx access logs reveals a massive spike in inbound traffic. Normal log patterns are completely overwhelmed.

03. Pattern Recognition

A single IP (198.51.100.42) is repeatedly requesting the resource-intensive `/search?q=dinner` endpoint. This is an HTTP Flood attack.

04. Mitigation Strategy

Immediate action required: Implement an `iptables` drop rule for the offending IP to restore CPU availability for legitimate traffic.
